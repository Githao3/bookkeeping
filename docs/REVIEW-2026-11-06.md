## 从代码发现的可靠性缺口

以下是代码层面的风险，尚未全部通过故障注入复现，不能视为本次已经发生的数据损坏。

1. 金额和余额使用 `Double`，输入也没有限制小数位或长度。建议以整数“分”存储人民币金额，明确两位小数的输入/舍入规则；表达式解析采用十进制计算。迁移已有数据前先做备份和迁移验证。
2. 保存只验证金额大于零，没有完整验证账户、分类和金额是否有效；新增账户把不能解析的余额静默转换成零（`AccountScreen.kt:379`）。应给出字段错误，禁止把错误输入悄悄改成另一笔金额。
3. UI 调用保存后立即关闭，ViewModel 的协程没有向界面提供保存成功/失败状态。应在真正写入成功后关闭，保存中阻止重复提交，失败保留输入并提供重试。
4. 新增和删除流水已经使用 `withTransaction`，这是应保留的基础；未来编辑流水也需要在一个事务内回滚旧余额影响并应用新影响。重复删除、失效账户和插入冲突也需要定义行为。
5. 数据库 `exportSchema=false`，还没有迁移测试；当前只有 3 条格式化单测。新增字段前应导出 schema、提供版本迁移，并增加金额、余额联动、编辑、转账、删除/归档、备份恢复方面的测试。
6. 首页同时订阅全部流水，统计在内存中聚合；每天的流水是在一个 LazyColumn item 内用普通 Column 完整渲染。当前数据量小，未实测卡顿；大量导入后应再评估分页、数据库聚合和逐行惰性渲染。

## UI 与排版建议

这部分是设计判断和改进方向，不代表布局目前全部失效。

- **保留现有首页层级和四项底栏。** 大金额、按日分组、右下角记账按钮易于识别。此前已按用户偏好简化的空状态文案可以保持，不需要再加回指导长句。
- **先重排记账区域。** 金额、分类选择、账户、日期备注、键盘的空间预算应按 360dp 小屏验收。分类可保留两行，但缩减顶部无功能留白，将日期/备注做紧凑辅助操作；键盘与保存按钮必须始终可达。
- **统一自定义控件和 Material 控件的配色。** 主界面绿/蓝，自定义选择蓝，账户弹窗和账户 chip 又出现默认紫色；容易让人觉得来自两套界面。设定统一主操作色和选择色，分类颜色继续用于表达类别。
- **适度提高辅助文字可读性。** 底栏 10sp、分类 11sp，部分灰字偏淡；优先提高到适合实机阅读的字号和对比度，再用结构节省空间。金额列可使用等宽数字特性保持对齐。
- **保留小图标外观，同时给控件留足触控区域。** 月份箭头视觉尺寸仅 32dp；Compose 可能自动扩展点击范围，但仍应预留至少 48dp 布局空间，避免与邻近目标冲突。分类、分段开关、底栏补充选中状态语义，并实际验证 TalkBack。
- **统计应回答问题。** 当前大圆环占用较多首屏，只有一个分类时信息很少。可缩小圆环，把分类排名和“比上月多花多少 / 日均支出”提前；点击分类进入对应流水。后续增加按日或按月趋势图。
- **减少深色模式中的描边和发光边缘。** 目前暗色记账界面每个数字键、金额框和分段开关都很突出。优先用背景层次区分，让键盘、文字和主操作更集中；玻璃质感可以保留，不必全面重做。
- **设置页展示用户真正能调的内容。** “iOS 液态玻璃 (Kyant0 Backdrop AGSL)”属于实现说明，在手机上还会换行占空间。可替换成主题、默认账户、金额隐藏、备份位置、导出范围等真实选项。版本信息应读取真实构建数据；当前安装包是 Debug，而文案固定写 Release Build / 最新版。
- **补齐长内容状态。** 长账户名、大金额、长备注、较大系统字号都需要测试；备注被截断时应能在详情看到全文。浏览历史月份后记新账，需明确记录日期和保存反馈，避免用户在当前列表找不到刚保存的记录。

## 功能迭代建议

| 迭代 | 范围 | 验收重点 |
| --- | --- | --- |
| 第一轮：核心可信 | 金额解析和精度、小屏键盘、字段校验、保存反馈、默认零余额、同账户转账限制、删除/归档规则 | 正常金额与边界金额算对；键盘完整可见；失败不丢输入；余额与流水一致。 |
| 第二轮：日常可用 | 账单详情与编辑、搜索备注、账户/分类/日期筛选、账户编辑与初始余额调整、自定义分类和排序 | 错账可以改；老账可以找；常用账户与分类可以配置。 |
| 第三轮：能长期使用 | 真实 CSV 导出、完整备份与恢复、月度与分类预算、统计期间与趋势、主题与隐私设置 | 在另一份本地测试数据中恢复后，流水、账户、分类、转账关联和余额都一致；统计与筛选范围一致。 |
| 后续按需求扩展 | 周期账单/提醒、退款、信用卡还款与资产负债区分、记账模板、桌面快捷入口 | 先定义业务口径；退款和还款不能被误算成普通收入或重复支出。 |

不建议当前同时铺开云同步、OCR、AI 分类和社交等功能。先把离线记账闭环做可靠，再根据实际使用需求选一项扩展。
